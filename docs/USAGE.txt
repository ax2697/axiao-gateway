WorkBuddy 网关（workbuddy2api 面板版）便携包 使用说明
==========================================================

版本：v1.13.0（windows-amd64 官方 Release 二进制）
来源：github.com/linguo2625469/workbuddy2api-panel
协议：MIT

这个包是「绿色便携版」，不需要安装、不需要 Python、不需要 Docker，
解压后双击一个 bat 就能跑。


一、运行环境
----------------------------------------------------------
Windows 10 / 11 64 位。仅此要求，无其它依赖。
（32 位系统、ARM 版 Windows 不支持，这个是 amd64 编译的。）


二、启动
----------------------------------------------------------
1. 把整个压缩包解压到一个固定目录，例如 D:\workbuddy-gateway
   （不要放在 C:\Program Files 之类需要管理员权限的地方，
     也不要放在会随软件升级被清空的程序安装目录里）
2. 双击「启动网关.bat」
3. 会弹出一个黑色命令行窗口，看到监听信息就是起来了
   ★ 这个窗口就是服务本身，关掉窗口 = 停止服务，用的时候别关

这个包已经预置好 config.json，开箱即用，注意三件事：

  · 监听地址是 127.0.0.1:7863 —— 只有本机能访问，安全
  · 预置的 api_key（面板和接口共用，便携版出厂值）：
        sk-QxgVEFVZM6Pg8Z6MfeiCA6TS
  · 拿到包的不止你一个人时，请务必改成自己的：
    用记事本打开 config.json，把 "api_key" 的值换成任意长随机串，
    保存即生效（该字段热生效，不用重启；但已填旧 key 的客户端要同步改）

如果想每次开都随机生成新密钥，直接删掉 config.json 即可，
程序会在下次启动时自动生成一份并打印一次；不过那样监听地址会回到
默认的 ":7863"（= 所有网卡），需要自己再改回 127.0.0.1:7863。


三、打开面板
----------------------------------------------------------
浏览器访问：http://127.0.0.1:7863/panel/

如果弹出要密钥，填上面那个预置的 api_key。填一次浏览器会记住
（存在 localStorage 里，换浏览器/清缓存要重填）。

面板能看：账号池、每个账号的积分与到期时间、任务中心
（自动签到/成长任务/积分刷新）、请求日志、运行配置。


四、加账号（必须做，否则接口调不通）
----------------------------------------------------------
面板右上角「添加账号」→ 打开授权链接 → 用你自己的
WorkBuddy / CodeBuddy 账号登录授权 → 回到面板刷新。

凭证保存在同目录的 auths\ 里（每个账号一个 json）。
账号池为空时，任何 API 请求都会失败，这是最常见的新手坑。


五、接到客户端
----------------------------------------------------------
Base URL : http://127.0.0.1:7863/v1
API Key  : config.json 里的 api_key（便携版出厂预置 sk-QxgVEFVZM6Pg8Z6MfeiCA6TS）
模型     : 打开 http://127.0.0.1:7863/v1/models 看可用名字，
           照抄，自己编一个不存在的模型名会报错

命令行自测：

  curl -X POST "http://127.0.0.1:7863/v1/chat/completions" ^
    -H "Authorization: Bearer 你的api_key" ^
    -H "Content-Type: application/json" ^
    -d "{\"model\":\"deepseek-v4.1-flash\",\"messages\":[{\"role\":\"user\",\"content\":\"你好\"}]}"

支持自定义 OpenAI 端点的客户端（Cline、Cherry Studio、NextChat、
各类 OpenAI SDK）都可以直接填。


六、目录说明
----------------------------------------------------------
wb2api.exe          主程序，8.7MB 单文件，前端已打包进二进制
启动网关.bat        双击启动（等价于 wb2api.exe）
config.json         运行配置（本包已预置好，删掉会自动重新生成）
config.example.json 官方配置模板，字段含义看这里
README.md           官方完整文档（很详细，出问题先查它）
auths\              账号凭证，每个账号一个 json ★不要外发
data\               运行状态和请求日志（默认保留 7 天）


七、配置怎么改
----------------------------------------------------------
改 config.json 后部分字段热生效（api_key、冷却、指纹清洗等），
其余需要重启。常用字段：

  listen    监听地址，默认 127.0.0.1:7863
            想让局域网其他设备也能用，改成 0.0.0.0:7863
  api_key   网关鉴权密钥；留空 = 不鉴权直接放行
  pool      账号池参数（并发、熔断、优先用快过期的积分等）
  schedule  定时任务时间（签到 9/21 点、成长任务 1 点等）

也可以用环境变量覆盖，前缀 WB2A_，例如
  WB2A_LISTEN=127.0.0.1:8788
  WB2A_API_KEY=xxx


八、安全提醒（重要）
----------------------------------------------------------
1. auths\ 目录里是明文的 accessToken / refreshToken，
   谁拿到这个目录就等于拿到这些账号，绝对不要打包发给别人、
   不要传到网盘或群里。
2. 本程序没有内置 TLS。默认只监听 127.0.0.1 是安全的；
   一旦改成 0.0.0.0 暴露到公网，必须设置强 api_key 并前置
   反向代理，否则等于把自己的账号额度公开送人。
3. 这类网关是逆向客户端登录态实现的，可能违反上游服务条款，
   存在账号被限流/封禁的风险。请只在自己账号、自己机器上自用。


九、常见问题
----------------------------------------------------------
Q: 双击后窗口一闪就没了
A: 说明启动失败。在目录里按住 Shift 右键 →「在此处打开
   命令行窗口」，输入 wb2api.exe 回车，看红色报错信息。

Q: 面板能开，但调用接口报无可用账号
A: 账号池是空的，去面板「添加账号」登录授权。

Q: 端口 7863 被占用
A: 改 config.json 的 listen，或设环境变量 WB2A_LISTEN。

Q: 换了台电脑，账号还得重新加吗
A: 把整个目录拷过去（含 auths\）就不用重登；只拷 exe 就要重登。
   注意拷 auths\ 等于拷贝账号，只在自己设备之间传。

----------------------------------------------------------
十、0.9.x 加的功能怎么用
----------------------------------------------------------

下面这些不是必用的，用到哪个看哪个。

【给朋友用：访问 Key】
  位置：图像与视频 → 本地网关 API →「谁能用」
  1) 点「生成一个 Key」
  2) 在名字那格写清楚给谁（三个月后你还知道）
  3) 「/天」是每天最多多少次，「/分」是每分钟最多多少次，留空不限
  4) 点一下密钥那格（显示 …a3f9 的位置）→ 展开完整 Key 并自动复制
  5) 把 Key 和地址 http://你的IP:7864/v1 发给他
  不给用了就点「停用」，立刻失效。
  ⚠ 没生成任何 Key 时，接口是全开的——本机任何程序（包括网页）都能调。
    只自己用没问题，要给人才需要设。

【一家渠道挂了，自动换下一家】
  不用配，默认就有。
  只有「限流(429) / 服务器错误(5xx) / 连不上」才换渠道；
  参数填错、Key 不对这类不换（换谁都一样，只会白烧额度）。
  长文档报「超出上下文」也会自动换窗口更大的渠道；
  明显装不下的会提前跳过，不会白跑一趟。
  上游管理页能看到哪个渠道在「冷却中 29s」，点「立即恢复」可以提前解除。

【重复问题不重复花钱】
  位置：同一个页面，勾上「响应缓存」。
  10 分钟内一模一样的问题直接复用上次答案。
  这几种不缓存：温度大于 0、带工具调用、要多个候选、流式——那些本来
  就该每次不一样，缓存了反而奇怪。

【选路策略】
  位置：同一个页面的「选路策略」。
  「轮转」= 多个 Key 平均分摊（默认）。
  「按健康度」= 按最近成功率排序，最稳的先用；新加的渠道会先给它机会。

【文生音乐】
  位置：图像与视频 → 模式选「文生音乐」。
  只在本机装了「阿晓豆包桥」并启动（127.0.0.1:9090）时可用。
  没装就用不了，别的平台基本没有音乐接口。

【出问题怎么查】
  每个请求都有一个 req_xxxxxxxx 的号。
  客户端的响应头里能看到（X-Request-Id）。
  面板「运行日志 → 网关服务日志」里搜这个号，能看到这次请求走到哪个
  渠道、跳过了谁、流式发了多少帧、最后为什么失败。
